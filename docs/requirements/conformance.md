## Spec lines that no longer match the code

The requirement text was left as it is. These lines drifted and need a new revision of the contract (Devin to decide):

- C-16 says the dashboard proxy `AREAS` gains `connections`; the code uses a dedicated `connectionsRouteAllowed`.
- C-20 says CSP `base-uri 'self'`; the code sends `'none'`, which is stricter.
- C-21 names the public route `claim`; the code route is `redeem-claim`.
- C-22 says "advisory lock" and one `seal_key_id`; the code uses the `shopify_locks` lease and `access_key_id` plus `refresh_key_id`.
- C-24 says an uninstall body carries `domain` / `myshopify_domain`; the code checks `myshopify_domain` only (`domain` is the custom domain).
- C-24 lists 401 as the only error answer; the route also answers JSON 413 (body over 256 KiB) and 400 (unreadable body), as the other webhook routes do.
- PL-8 lists `voice.textback.optin` as allowed and then as "not" allowed (plans.md); the code excludes it.
- C-26 lists `SUPABASE_URL` (code: `ZS_TARGET_REF`), says seven operations (code: nine) and three new tables (code: four, with `shopify_locks`).

## Method

Each rule was mapped from the spec text to code and tests by reading both. Each gap was then closed one at a time with a test that fails when the behaviour is removed (mutation checked on the key ones). Tests run with `ZS_TEST_DATABASE_URL=... pnpm vitest run <file>` in the touched package.
